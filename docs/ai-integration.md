# AI 接入规范

## 能力边界

所有 AI 模型服务商都必须实现 `WorkItemGenerator` 接口。当前 DeepSeek 通过 Spring AI 的 OpenAI 兼容适配器接入。

应用服务只能使用与服务商无关的 `WorkItemGenerator.GenerationResult`，不得直接依赖 DeepSeek 或其他服务商的 SDK 和响应对象。

## 提示词管理

- 提示词统一存放在 `src/main/resources/prompts`。
- 提示词变更视同代码变更，需要评审、测试和版本管理。
- 输出行为或结构要求发生变化时，需要更新 `deepseek.prompt-version`。
- 不得把用户输入拼接到系统指令中；需求内容应作为用户消息单独传入。
- 提示词必须明确输出层级、字段约束和禁止扩展需求等边界。

## 结构化输出

- 优先让 Spring AI 将模型响应转换为明确的 Java 类型。
- AI 响应转换成功后，仍需校验根节点、节点名称、最大层级、工作项类型和优先级范围。
- JSON 格式正确不代表业务结果有效，未通过领域校验的数据不得写入数据库。
- AI 响应结构只能在 `infrastructure/ai` 中使用，不得直接作为 HTTP 响应或数据库对象。

## 安全与运行要求

- API Key 只能通过环境变量或密钥管理服务提供。
- 不得记录完整提示词、完整需求内容、API Key 或 AI 服务商的原始错误响应。
- 保存模型名称和提示词版本，便于问题追踪和结果复现。
- 上线前需要配置调用超时、仅针对可重试异常的有限重试，以及调用量、耗时和失败率监控。
- 需求文本和模型结果可能包含敏感内容，需要明确保存期限和清理策略。
