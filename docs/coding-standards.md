# 编码规范

## Java 规范

- 使用 Java 21。
- 优先使用构造器注入，以及不可变的 `record` 或值对象。
- 固定范围的业务状态必须使用枚举，不得使用字符串直接比较业务状态。
- 一个方法只承担一个主要职责。
- AI 服务商特有逻辑不得进入应用服务。
- 应用异常必须包含稳定的错误码，不得向调用方暴露 AI 服务商的原始响应内容。

## Spring 规范

- Controller 不得包含业务逻辑。
- 必须原子提交的持久化操作，应在基础设施层 Repository 实现上设置事务边界。
- 需求拆解任务只能使用指定的拆解线程池。
- 业务配置应通过带类型的 `@ConfigurationProperties` 对象读取。
- 不得在业务类中直接读取散落的环境变量或配置字符串。

## MyBatis 和数据库规范

- 数据库变更使用 `src/main/resources/db/migration` 下的 Flyway 迁移文件。
- 每次结构变更都必须新建迁移文件，不得修改已经在非本地环境执行过的迁移。
- 简短且易读的 SQL 可以使用 Mapper 注解；复杂查询应迁移到 Mapper XML。
- MyBatis 数据对象只能在基础设施持久化层使用。

## 测试规范

- 应用层状态流转使用不启动 Spring 容器的单元测试覆盖。
- 工作项树校验需要覆盖空节点、超过四级、非法优先级等异常情况。
- Controller 需要覆盖参数校验和响应契约测试。
- Mapper SQL 或 Flyway 迁移发生变化时，需要增加基于 MySQL 的集成测试。
